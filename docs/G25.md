# G25: controlled same-host product-route comparison

**Real-host status: run on three hosts (2026-10-03).** `g25-rtx5090-20261003f` (omp-ninfer v0.10.0 Docker lane),
`g25-rtx4090-20261003a` and `g25-rtx3090-20261003e` (native lanes), each with a G25 pass receipt in its fifth-tuple
draft release; results in `docs/MEASUREMENTS.md`. All ran on the hosts' normal accounts, not a restricted evaluation
account. Host-free tests and stock-OMP mock proofs do not qualify G25. No profile, qualification ledger or existing
NInfer installation is upgraded by this tooling.

## What the comparison means

G25 compares stock Strata serving Qwen3.8-Flash-Next Coder over Chat Completions with an
already installed stock NInfer serving Qwen3.8 27B over its documented native Responses
route. Both use **one identical, size- and SHA-256-pinned stock OMP executable**, the
frozen `synthetic-1` G24 six-task evaluation, prompts, external immutable verifiers,
tools, output caps and budgets. `scripts/evaluate.py`, `eval/support.py`, fixtures and
`eval/tasks.json` are unchanged. The separate G25 runner imports their primitives and
has one attempt path for both arms.

The comparison class is `same_host_product_route`, never an engine-only experiment.
Engine, model, quantization and API/client-adapter behavior all differ. Matched task
and attempt numbers are not seed-controlled model trials. Earlier G24 scores, NInfer
headlines and historical receipts cannot be mixed into this batch.

A complete real evaluation can support the factual statement “On the fixed
18-attempt-per-arm, same-host batch, Strata completed X and NInfer completed Y,” with
host, both model/quant/protocol identities and the failure denominator included. It
does not automatically say Strata won. The frozen default claim policy requires:

* **Higher verified completion count in this batch:** at least three more Strata
  verified completions out of 18, and more Strata-only than NInfer-only successful pairs.
* **Faster on jointly successful paired attempts in this batch:** at least 12 jointly
  successful pairs with observed timings, median Strata/NInfer task-wall ratio at most
  0.80, and no greater Strata total wall cost across **all** attempts, including failures.
  Missing timing excludes a pair and prevents an all-attempt speed comparison if any
  total is unavailable; it is never imputed as zero.
* `claims.engine_only_comparison` remains `false`. Neither claim generalizes to a
  “better model,” all workloads, or an engine-only speedup. Daily-backend preference
  does not change qualification requirements.

## Private workspace and prerequisites

Use a restricted evaluation account, no unrelated credentials, and host-level network
observation. The integration is not a sandbox for auto-approved coding tools. Run on
one GPU host, with both installations already independently verified. The NInfer lane
must be `rtx3090-native` or `rtx4090-native` (installed Windows controller), or
`rtx5090-docker-local` (the installed Docker Desktop WSL2 container, provider
`ninfer-beta`); tunnel and Docker fragments are not interchangeable. Only one engine may
own the GPU per window. Engine start/stop and host observation are operator actions
through each installation's supported controller; the comparison harness never
starts, stops, installs or modifies either engine.

### Operator kit

* `scripts/g25_host_probe.py --arm strata|ninfer --config <private json>` is the read-only
  host observation for `host_probe_argv`: `nvidia-smi` owners, CIM memory/commit/disk, driver,
  power plan, and a private snapshot of non-loopback TCP connections of the owned processes.
  An engine executable under an arm's root owns the GPU even when WDDM lists it as `C+G` (the
  native NInfer server on a display-attached RTX 3090 is); other graphics clients are excluded
  only on display-attached hosts. The host block records the GPU's default power limit: a
  native NInfer lane enforces its qualified limit (300 W on the RTX 3090) only while it owns
  the GPU, so the enforced limit is part of that arm's route, not host state. Every host
  command gets `ProgramFiles`, which NVML needs and the evaluator's clean environment drops.
* `scripts/g25_host.py prepare --config <private json>` writes `identities.json`,
  `state/bindings.json` and the draft plan into a new owner-only comparison root; it needs the
  NInfer lane already ready. `scripts/g25_host.py run --sequence all` (or `--step pilot-strata`,
  `pilot-ninfer`, `window-1`..`window-6`) stops the previous owner through its configured
  controller, verifies GPU release, cold-starts the next arm, records switch/startup times for
  the probe, then calls `compare_g25.py pilot|run-window` once per reserved step.
* The Docker lane binds a private `docker_identity_probe_argv`: one read-only JSON object with
  release id, running container id/start time, inspected image digest, publications, the
  authenticated `/v1/ninfer/status` binary/config/model hashes and deployment profile, and
  the container's own TCP rows. Its digest and hashes must match the selected omp-ninfer
  release manifest; the client dials `127.0.0.1` only.
* `scripts/probe_g25_speed.py` is a separate, comparison-only client-side speed probe (TTFT
  and client-observed output rate at fixed prompt depths, one shared prompt set per host).
  Its samples are never part of G25 scoring.

Create a new private comparison root **outside** both installation roots, the repository
and the default OMP HOME. Use an owner-only directory/ACL and owner-only bindings and
key files (mode 0600 on POSIX; the restricted account's ACL on Windows). Never pass a
key in argv. The NInfer adapter sets the environment-backed `NINFER_NATIVE_API_KEY` and
`PI_OPENAI_STATEFUL=1` only in each isolated attempt HOME; Strata retains the production
launcher restrictions and its own key. No cloud fallback, proxy, Responses shim,
plugin, daemon, engine-state migration or global OMP config change is introduced.

The commands below use PowerShell private variables; assign them to the operator's
already verified local paths, not to values copied from another installation:

```powershell
$Comparison = Join-Path $env:USERPROFILE "g25-private\comparison-a"
$Identities = Join-Path $Comparison "identities.json"
$Bindings = Join-Path $Comparison "state\bindings.json"
$Draft = Join-Path $Comparison "comparison-draft.json"
$Plan = Join-Path $Comparison "comparison-plan.json"
$Release = Join-Path "releases" $ProfileId
```

`$ProfileId` identifies the new, exact Strata profile under comparison. A changed stock
component, model, quant or setting requires its own profile/root/ledger. Planned RAM
upgrades are not measurements. Record actual installed RAM and observed available
RAM/commit/disk, driver, OS/build, VRAM, power and clock policy before every dispatch.
Do not publish private machine names, addresses, serials, UUIDs or user paths. Host
labels are `rtx3090-win-a`, `rtx4090-win-a` or `rtx5090-win-a`.

### Identity input and private bindings

Prepare `$Identities` as JSON with exactly the public `omp`, `strata`, `ninfer` and
`host` objects defined in `schemas/comparison.schema.json`:

* `omp`: platform, version, executable byte count and SHA-256; both adapters recheck the
  same file and require the selected Strata profile's stock OMP pin.
* `strata`: profile ID/fingerprint, release-manifest and installed runtime identity
  hashes, exact served model ID/model identity hash, quantization, `openai-completions`,
  and provider `strata-local`. These are identities, not labels selected to match a run.
* `ninfer`: native lane, exact release ID/manifest SHA-256, installed runtime/config/model
  identity hashes, served model ID, quantization, `openai-responses`, and native provider
  `ninfer-native-3090` or `ninfer-native-4090` respectively.
* `host`: neutral label, OS/build, GPU model/VRAM, driver, power/clock policy, and minimum
  total RAM, available RAM, commit headroom and disk (`min_*_gib`).

Prepare `$Bindings` as a private JSON object; it is never exported:

| Field | Value |
|---|---|
| `schema_version`, `comparison_id` | `1`, the same safe comparison ID as the plan |
| `comparison_root`, `omp_binary` | Absolute private comparison root and the one stock OMP executable |
| `execution_boundary` | `evaluation` for the real host; `host_free` only for mock proofs |
| `strata` | `root`, `profile`, `manifest`, `key_file`, `port` |
| `ninfer` | `root`, `manifest`, `key_file`, `port`, `controller`, `state_root`, `status_file` |
| `host_probe_argv` | JSON argv array for the operator's read-only fresh host observation command |

All paths are absolute and private. Key/controller/state paths must stay inside their
installation. `profile` points to the exact Strata profile. Each `manifest` is the
read-only exact release-manifest file whose bytes are pinned in the public plan. The
Strata model identity is SHA-256 of canonical JSON of the profile `model` object;
installed runtime identity is checked against the verified installation record.
`status_file` is a normalized
read-only capture under the private comparison root, not a writable NInfer state file.
The comparison directory must not enclose either installation or the default OMP HOME.

For NInfer, capture its installed controller `-Action Status` output and authenticated
native status privately. Normalize `status_file` to `release_id`, `endpoint_state:
"ready"`, `runtime_identity_sha256`, `config_identity_sha256`, and
`model_identity_sha256`. These last three map respectively to the documented native
served identity's `binary_sha256`, `config_sha256`, and `model_artifact_sha256` (the
native `omp-client-probe.py` identity contract). Do not invent health-response fields.
The adapter also authenticates `/v1/models` and `/v1/ninfer/status`, requires `status:
"ok"` and `identity.source_dirty: false`, and matches the same served identity hashes.
It refuses redirects and ambient proxy use. Preserve original captures privately.

The host probe receives `--arm strata` or `--arm ninfer` and must return one JSON object
within 60 seconds, no banners or secrets. It must freshly measure/observe, not replay a
fixture. Its mandatory contract is:

* `host`: `label`, `os`, `os_build`, `gpu_model`, `vram_mib`, `driver`, `power_policy`,
  `clock_policy`, exactly matching the plan.
* Measured `ram_gib`, `available_ram_gib`, `commit_headroom_gib`, `disk_gib` at or above
  the predeclared floors; `gpu_owners` exactly `["strata"]` or `["ninfer"]`, with all
  unrelated compute owners excluded by the host observation.
* `process_condition: "process-cold"` for that window's fresh engine process;
  `file_cache_condition: "cold"`, `"warm"`, or `"unknown"`. An unknown file-cache state
  requires `missing_reasons.file_cache_condition`. Process-cold is **not** evidence that
  filesystem caches were cold. Restart even for the two consecutive same-arm windows.
* Independently observed `startup_ms` and `switch_ms`; switching must be at most 300,000
  ms. `switch_ms` covers the full stop/release/start/readiness interval (startup is
  its separately reported subset). The first switch is charged explicitly; subsequent
  switches are already inside campaign elapsed time. Keep both separate from
  task/request/server times.
* `network_observation_sha256`: hash of the private network observation; `route_escape:
  false`, `credential_exposure: false`, `controller_ok: true`; `missing_reasons: {}` for
  fully observed required values. Unavailable mandatory safety observations abort.

The host probe is `scripts/g25_host_probe.py` (operator kit above). The installed controller and host observation
tooling are prerequisites for real dispatch, not mock-backed fallbacks. The harness never treats self-reported
success as a GPU proof.

## Plan, pilot and freeze

```powershell
python scripts/compare_g25.py init-plan --identities $Identities --comparison-id comparison-a --output $Draft
python scripts/compare_g25.py validate --plan $Draft --draft --bindings $Bindings
```

The draft can retain explicitly unresolved identity values for preparation; pilot and
finalization cannot dispatch with unresolved pins. All required fields must exist.
`init-plan` embeds the exact G24 identity/budgets, six-window schedule, default claim
policy, and comparison harness hashes. It never overwrites a plan.

Cold-start only Strata using its existing restricted launcher and verify exclusive GPU
ownership. Run the Strata pilot. Stop it with its supported controller; observe GPU
release. Cold-start the installed native NInfer and run its pilot:

```powershell
python scripts/compare_g25.py pilot --plan $Draft --bindings $Bindings --arm strata
python scripts/compare_g25.py pilot --plan $Draft --bindings $Bindings --arm ninfer
```

These are **two operator-controlled exclusive pilot windows**, not simultaneous
commands. Each pilot runs one attempt of every task and is explicitly non-scored.
Inspect private artifacts, protocol compatibility, identity checks, cap behavior and
all failures. Ordinary verifier failures are results, not permission to substitute
another attempt. An aborted or incomplete pilot cannot freeze a plan. If a pilot fix
changes harness bytes or any experiment boundary, use a new comparison ID/root and
repeat both pilots; never relabel old pilot artifacts.

```powershell
python scripts/compare_g25.py init-plan --identities $Draft --output $Plan --finalize --pilot-root $Comparison
python scripts/compare_g25.py validate --plan $Plan --bindings $Bindings
```

Freezing binds both pilot hashes and their execution boundary. The canonical plan hash
covers its entire JSON object (no self-hash). Pilot matching excludes only draft/frozen
state and the final pilot references. A scored dispatch hashes the comparison harness,
frozen evaluator/fixtures and pinned OMP again. Never edit the plan after freezing.

## Six scored windows

The exact schedule is:

| Window | Arm | Attempt | Task order |
|---|---|---|---|
| 1 | Strata | 1 | bugfix-a, bugfix-b, multifile-regression, tool-loop, long-context, continuation |
| 2 | NInfer | 1 | same frozen order |
| 3 | NInfer | 2 | multifile-regression, tool-loop, long-context, continuation, bugfix-a, bugfix-b |
| 4 | Strata | 2 | same rotation by two |
| 5 | Strata | 3 | long-context, continuation, bugfix-a, bugfix-b, multifile-regression, tool-loop |
| 6 | NInfer | 3 | same rotation by four |

Before **each** command, stop the previous engine, verify release of the GPU,
cold-start the specified arm, recapture controller/host state and observe the route.
There must be no competing GPU engine, even between windows 2/3 or 4/5. Switching and
idle intervals remain inside the 40,000-second campaign wall boundary. Do not reboot
the host during the campaign; a changed monotonic epoch/clock discontinuity aborts.

```powershell
python scripts/compare_g25.py run-window --plan $Plan --bindings $Bindings --window 1
python scripts/compare_g25.py run-window --plan $Plan --bindings $Bindings --window 2
python scripts/compare_g25.py run-window --plan $Plan --bindings $Bindings --window 3
python scripts/compare_g25.py run-window --plan $Plan --bindings $Bindings --window 4
python scripts/compare_g25.py run-window --plan $Plan --bindings $Bindings --window 5
python scripts/compare_g25.py run-window --plan $Plan --bindings $Bindings --window 6
```

These commands deliberately do not automate engine lifecycle or copy NInfer state.
Every attempt gets a fresh worktree and isolated HOME. Task wall time is monotonic from
materialization through verifier completion. Phase wall times, unavailable independent
request/server times, startup and switching are separate fields. Every unavailable
measurement is `null` with a reason. A result is verified only when the immutable
verifier passes, all required phases complete, and no timeout, cap breach, protocol
error, unsafe workspace or missing transcript invalidates the frozen G24 boundary.

### Abort and interruption policy

Stop future dispatch on changed frozen/harness bytes, wrong identity or endpoint,
concurrent GPU ownership, route escape, credential exposure, unsafe workspace,
controller/switch failure, host drift below the declared floors, two consecutive
observed OOMs in either arm, interruption, or the comparison wall cap. Ordinary task,
verifier or protocol failures remain in the denominator and do not cause selective
reruns. No repeat of a scored attempt is permitted under the same comparison ID.

Windows reserve their directory exclusively and atomically publish records. Existing
windows and interrupted reservations cannot be overwritten or resumed. A following
window requires a finalized predecessor. A caught safety abort finalizes the current
window with all undispatched slots retained as failures; later windows can record
only undispatched failures without invoking either adapter. Such data cannot pass
G25. An interrupted/incomplete predecessor blocks later windows; retain it for
investigation and start a new ID/full schedule after resolution. Never remove a failed
result to make the runner advance.

## Summarize, review and export

```powershell
python scripts/compare_g25.py summarize --plan $Plan --root $Comparison
```

This requires all six windows and all 36 scheduled outcomes. It makes **no model call**,
validates every attempt/window/artifact hash, pairs by `(task_id, attempt_number)`, and
computes complete/failure counts over 18 per arm, paired outcomes, all-attempt wall
cost including failures, explicitly labeled success-only timing, and the predeclared
claim decision. Host-free runs can never emit an authorized factual/superiority claim.

Review the generated plan, paired summary, six window aggregates and verifier aggregate
for private data and unsupported interpretation. Raw events, transcripts, patches,
changed files, network logs, key files, bindings and NInfer state stay private. The
export path must be a **new** directory inside the exact Strata release's `evidence/`.
After human review:

```powershell
$Export = Join-Path $Release "evidence\comparison-a"
python scripts/compare_g25.py summarize --plan $Plan --root $Comparison --export $Export --review-ack "I reviewed all public comparison artifacts"
python scripts/check_public_hygiene.py
```

Export recomputes the summary, refuses changed published bytes, rechecks all referenced
private artifact hashes, and requires explicit review acknowledgement. Public exports
contain only the immutable plan, paired summary, window aggregates, verifier outcomes
and a hash-bound review record. Pattern checks are a guard, not human publication
approval. Export does not update a receipt or ledger, and does not itself qualify G25.

## Receipt and release validation

Use the existing append-only `omp_strata.receipts.make_receipt`, `write_receipt` and
`update_ledger` APIs; do not edit historical receipts. The G25 evidence kinds are
`comparison_plan`, `paired_summary`, six `window_aggregate` references, and one
`verifier_aggregate`. Each reference is relative to the release and hashes the **exact
exported file bytes**; all are explicitly scrubbed. Record-internal `plan_sha256` is
the canonical entire-plan hash, which is distinct from pretty-printed file identity.

A passing receipt must be `gate_id: G25`, `execution_boundary: evaluation`, bound to the
new Strata profile/fingerprint and implementation commit, with `comparison` containing
`comparison_id`, `comparison_class: same_host_product_route`, exported `plan_sha256`,
`paired_summary_sha256`, `omp_binary_sha256`, `ninfer_manifest_sha256`,
`attempts_per_arm: 18`, `paired_attempts: 18`, and `engine_only: false`. Six valid
exclusive same-host windows, all 36 retained outcomes and no unresolved safety/identity
abort are required. `fail` and `blocked` remain failures for readiness when a release
claims comparison support. **Do not create a passing receipt from these host-free tests.**

After real-host execution and review, the following guarded recipe constructs the
receipt from the exported identities and appends it to the intended ledger; the 2026-10-03 receipts were made with
it, using the commit of the tooling synced to the host. **Never use synthetic fixtures for this step.** A real G25
failure needs a separate `fail`/`blocked` receipt describing the retained failure, not this pass recipe.

```powershell
$Implementation = git rev-parse HEAD
@'
import sys
from pathlib import Path
from omp_strata.comparison import load_plan, read_json, validate_summary
from omp_strata.common import sha256_file
from omp_strata.profile import load
from omp_strata.receipts import make_receipt, update_ledger, write_receipt

release, exported = (Path(value).resolve() for value in sys.argv[1:3])
if not exported.is_relative_to(release / "evidence"):
    raise SystemExit("export must be inside this release evidence directory")
manifest = read_json(release / "manifest.json")
profile = load(release / manifest["profile"]["path"])
plan = load_plan(exported / "comparison-plan.json")
summary = read_json(exported / "paired-summary.json")
if (validate_summary(summary, plan) or not summary["complete"]
        or summary["execution_boundary"] != "evaluation"
        or plan["strata"]["profile_fingerprint"] != profile.fingerprint
        or not summary["claims"]["factual_sentence"]):
    raise SystemExit("real, complete, profile-bound comparison required")
entries = [("comparison_plan", "comparison-plan.json"),
           ("paired_summary", "paired-summary.json"),
           ("verifier_aggregate", "verifier-aggregate.json")]
entries += [("window_aggregate", f"window-{number}.json") for number in range(1, 7)]
evidence = [{"kind": kind, "path_or_ref": (exported / name).relative_to(release).as_posix(),
             "sha256": sha256_file(exported / name), "scrubbed": True} for kind, name in entries]
comparison = {"comparison_id": plan["comparison_id"],
              "comparison_class": "same_host_product_route",
              "plan_sha256": sha256_file(exported / "comparison-plan.json"),
              "paired_summary_sha256": sha256_file(exported / "paired-summary.json"),
              "omp_binary_sha256": plan["omp"]["sha256"],
              "ninfer_manifest_sha256": plan["ninfer"]["manifest_sha256"],
              "attempts_per_arm": 18, "paired_attempts": 18, "engine_only": False}
receipt = make_receipt(gate_id="G25", status="pass", execution_boundary="evaluation",
    implementation_commit=sys.argv[3].strip(), profile_id=profile.id,
    identity_fingerprint=profile.fingerprint,
    expected="Six exclusive same-host windows and 36 retained matched outcomes",
    observed=summary["claims"]["factual_sentence"], evidence=evidence,
    limitations=summary["confounders"], comparison=comparison)
path = write_receipt(release / "receipts", receipt)
update_ledger(release / manifest["qualification"]["ledger"], path)
'@ | python - $Release $Export $Implementation
```

Refresh only the manifest/ledger hash binding after the append, then require readiness:

```powershell
python scripts/verify_release.py --manifest (Join-Path $Release "manifest.json") --rebind --require-ready
```

This must resolve/hash-check evidence within the release, bind the Strata and OMP pins,
verify both arms' paired outcomes and apply the frozen claim policy. A G25 pass records a complete, valid
comparison, not a winner; `--require-ready` still refuses a draft release whose other gates have not run.

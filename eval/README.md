# Bounded coding evaluation (synthetic-1)

This is six independent, original synthetic Python/stdlib tasks, not borrowed benchmark scores.
The model sees only a fresh workspace and that task's prompt(s), never the verifier, generator,
manifest, or reference patch. The authoritative verifier stays outside the writable worktree and
runs hidden and frozen visible tests in another Python interpreter. It hashes visible tests and
all declared immutable contracts/data before and after executing candidate code; changing or
suppressing them fails the attempt. Reference patches are host-free solvability witnesses, not
inputs to the coding agent.

| Task | Category | Visible seed tests |
| --- | --- | --- |
| bugfix-a | Interval subtraction bug | fail |
| bugfix-b | Incremental Unicode decoding bug | fail |
| multifile-regression | Catalog import, canonicalization and quote cache | fail |
| tool-loop | Inspect CSV, repair settlement stages, exercise CLI and tests | fail |
| long-context | Retrieve an approved archival policy and change code | pass (hidden regression fails) |
| continuation | Capture calibration, restart client, resume and implement | pass (hidden regression fails) |

## Host-free proof

From the repository root:

    python3 scripts/evaluate.py --dry-run
    python3 -m unittest tests.unit.test_eval_fixtures -v

Dry-run validates every frozen hash, creates six temporary Git workspaces, confirms each seed
fails its immutable verifier and each reference patch passes, and removes the temporary trees.
No OMP, GPU, network, or external Python dependency is needed. The script does not commit anything.
The unit module also contains a real-stock-OMP continuation smoke. It skips explicitly when
OMP_STRATA_OMP_BINARY is unset/absent. With that variable pointing to the fetched stock binary,
the test runs two fresh clients against a loopback scripted provider, removes the calibration
instrument between them, checks the replayed tool result, and requires the immutable verifier to
pass. It is a client/harness proof, not a model-quality or GPU result.

The large archive is generated by eval/generate_corpus.py with fixed seed 6042042. It is not
committed as hundreds of kilobytes, and the generator is not copied into a model workspace.
The manifest pins both generator bytes and the fully generated tree hash. Per-task files,
Unicode character counts, and estimated tokens (characters / 4) are recorded in tasks.json.
The long-context archive is 60-80K estimated tokens. This is a corpus-size estimate, NOT a
measurement of a model's actual input: the agent must retrieve the needed policy, not ingest the
whole corpus by default. Real tokenizer measurement and actual request token counts remain
not_run/null until measured on the selected model. This fixture does not qualify near-capacity
128K behavior, compaction, or context-window acceptance by itself.

## Frozen scoring boundary

* 900 seconds per attempt, including materialization, client/tool calls, phase hook and verifier.
  The harness reserves 30 seconds for verification and gives OMP only the remaining time.
* 40 tool calls total across all phases; the supervisor aborts when a completed toolCall record
  exceeds the cap. It counts authoritative message_end blocks, not repeated agent_end snapshots.
  Cancellation races are not a sandbox guarantee: an already-dispatched tool may have started.
* 32,768 output tokens per model response, enforced by the pinned profile's model limit;
  131,072 reported output tokens per attempt. Missing provider usage remains unknown, not zero.
* 32 MiB captured JSON events and 1 MiB stderr per client phase (separate hard capture limits).
* Hidden/visible verification has a 25-second child-process ceiling, 64 KiB output cap;
  the outer verification boundary is 30 seconds. Workspaces over 4,096 files or 8 MiB are unsafe.
* Three attempts per task = 18 scored attempts. Order is deterministic round-robin through the
  frozen task order (bugfix-a through continuation), then the next attempt number. Every workspace
  and client HOME is fresh. The total batch wall cap is 16,200 seconds. Two consecutive observed
  OOM failures, modified evaluation/verifier files, or an unsafe workspace stop further dispatch.
  Undispatched scheduled attempts remain explicit failures in the denominator.

Completion requires the immutable verifier to pass, all required phases to finish, valid protocol
and transcript capture, and no timeout or budget violation. Count verified passes over ALL scheduled
attempts, including failures, timeouts, crashes and retained skipped dispatches. Report task wall time
to the verified result with a monotonic clock; label success-only timings separately. Never discard a
failed run, rerun just failed tasks into the original batch, or score a persuasive final response.
Protocol counts distinguish malformed arguments, orphan results, missing results, duplicate/bad ids,
invalid event JSON and stopReason error/aborted. Argument errors are observed client-side errors;
OMP's tolerant stream parser may repair malformed upstream fragments before this layer can see them.

## Real route and continuation

Use a restricted account/container, offline fixture tools, and an independently enforced/observed
loopback-only network policy. This Python harness isolates HOME/config and the worktree but is NOT an
OS sandbox; arbitrary candidate Python and OMP bash tools can escape filesystem boundaries with the
same account's privileges. Never run it with production secrets or general host-administration rights.
The only deliberate credential passed to OMP is the local Strata key. The key is read from
STRATA_API_KEY or the integration's existing private state key file; it is never put on the argv.

Fetch/install the pinned stock OMP binary and start the independently qualified Strata route first.
Run one pilot pass, inspect its artifacts, fix harness problems, freeze a NEW evaluation version,
then start a scored batch (out must be new and beneath root):

    python3 scripts/evaluate.py --root <integration-root> --profile profiles/win11-rtx5090-coder-iq1m-131k.json --attempts 1 --pilot --out <integration-root>/evidence/eval-pilot
    python3 scripts/evaluate.py --root <integration-root> --profile profiles/win11-rtx5090-coder-iq1m-131k.json --attempts 3 --out <integration-root>/evidence/eval-scored

Scored mode refuses any frozen-file mismatch or profile output-limit mismatch. A pilot is explicitly
non-scored and records any drift. tasks.json pins all eval files except itself, plus evaluate.py, and
pins each seed/materialized workspace, prompt set, verifier and reference tree. Tree hashing is SHA-256
over canonical compact sorted-key UTF-8 JSON mapping relative POSIX paths to file SHA-256 values.
Git metadata, bytecode and __pycache__ are excluded. python3 eval/freeze.py intentionally re-freezes
before scoring; do not use it to conceal changes in an existing scored batch.

continuation phase 1 is read-only: OMP must actually run the calibration instrument and retain its
observation in the session. The harness checks the tool result and unchanged workspace, removes the
instrument/data, then starts a fresh stock OMP process with --continue and the same private session
directory. The follow-up prompt omits the calibration constants. Optional --between-phases '<command>'
executes an operator-supplied command as an argv list (no shell interpolation) between phases, bounded
to 120 seconds and the remaining attempt budget. Use an absolute executable path and quote arguments;
for an engine restart the command must wait for actual readiness. The hook receives the isolated OMP
environment. A failed hook fails the attempt. With no hook this still proves a fresh-client continuation
path. Engine restart/compaction is not inferred: actual compaction entries are counted, and any engine
restart, cold re-prefill, warm cache state, or reduced-threshold test needs separate route evidence.

Every attempt retains events, stderr, native JSONL sessions, changed-file bytes, a candidate patch,
verifier details and exit code, counts, budgets and monotonic timing under the private output directory.
The summary retains failures and uses null for unavailable startup, RAM/VRAM, actual tokenizer and
cache observations; it does not invent zero-valued measurements or conflate them with task wall time.
These raw artifacts may contain local paths and environment-derived output. Do not commit/upload them;
only publish a reviewed, scrubbed export. No default-OMP or NInfer state is modified.

Eighteen scored attempts are a bounded engineering sample, not a general benchmark or statistical
superiority claim. Host-free dry-run proves fixture solvability and scoring integrity, not Strata
coding quality. No GPU results, comparative claims, compaction guarantees, durable engine state,
or release qualification follow from these fixtures alone.
